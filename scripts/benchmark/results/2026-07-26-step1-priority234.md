# Stage 1 priority 2-4 optimization assessment

Date: 2026-07-26

Status: priorities 2 and 3 are retained as unconditional byte-exact
optimizations. Priority 4 is retained behind the existing experimental Level
1 optimizer selector. Priority 1 (PGEN storage work) was deliberately left
untouched.

## Scope and decisions

| Priority | Change | Numerical contract | Decision |
| ---: | --- | --- | --- |
| 2 | Reuse fresh resident logistic predictions within ordinary IRLS | Byte-exact | Retain unconditionally |
| 3 | Hand a single-trait binary Level 1 design directly from Level 0 to Level 1 when it remains resident | Byte-exact | Retain unconditionally |
| 4 | Apply safeguarded path-Newton continuation to Cox Level 1 ridge paths | Non-byte-identical opt-in | Retain experimentally; do not make default |

The implementation was split into the following commits:

```text
a23ef29 perf: reuse resident logistic predictions
83545f1 perf: retain single-trait binary level1 design
8d534c4 feat: add safeguarded Cox path corrections
3eb5843 feat: extend Level 1 path continuation to Cox
68030b7 build: include Cox ridge test in release checks
```

For survival analyses, both accelerated selector values request the same Cox
path-continuation implementation:

```bash
REGENIE_STEP1_LEVEL1_OPTIMIZER=path-newton regenie ...
REGENIE_STEP1_LEVEL1_OPTIMIZER=newton-cg regenie ...
```

There is no Cox Newton-CG implementation. The `newton-cg` value still adds
bounded Newton-CG after path continuation for eligible logistic fits; for Cox
it intentionally aliases `path-newton`.

### Priority 2: resident logistic prediction reuse

This comparison replayed the same retained Level 0 cache for eight binary
traits under ordinary IRLS. The control was revision `f55bdd2`; the candidate
was `68030b7`.

| Order | Revision | Level 1 (s) | Process wall (s) | Prediction evaluations | Prediction reuses |
| --- | --- | ---: | ---: | ---: | ---: |
| Control 1 | `f55bdd2` | 284.706 | 304.90 | 1,216 | 0 |
| Candidate | `68030b7` | 290.738 | 311.06 | 548 | 668 |
| Control 2 | `f55bdd2` | 298.331 | 318.72 | 1,216 | 0 |

Storage wait varied enough that total Level 1 time was not monotone across the
three-run bracket. Against the final control, the candidate reduced Level 1
by 2.55% (1.026x); against the first control it was 2.12% slower. The isolated
work moved in the intended direction: ridge-backend time fell from 14.037 to
7.357 seconds and validation from 2.746 to 0.571 seconds against the final
control.

All 508 IRLS iterations, line searches, weighted products, score evaluations,
and solves were preserved. Prediction evaluations plus explicit reuses remain
1,216. All eight LOCO outputs were byte-for-byte identical. This is a small,
low-complexity removal of redundant work, so it is retained despite noisy
storage-bound wall time.

### Priority 3: single-trait binary Level 0-to-Level 1 handoff

This comparison ran a complete N=500,000/M=700,000 single-trait binary job
with the mutually exclusive two-backend Level 0 pipeline disabled. The
control was `a23ef29`, immediately before the handoff change; the candidate
was `68030b7`.

| Order | Revision | Level 1 (s) | Internal total (s) | Process wall (s) |
| --- | --- | ---: | ---: | ---: |
| Control 1 | `a23ef29` | 41.218 | 156.107 | 159.91 |
| Candidate | `68030b7` | 30.892 | 148.075 | 151.00 |
| Control 2 | `a23ef29` | 41.519 | 155.899 | 160.02 |

Against the final control, Level 1 improved by 25.59% (1.344x), the internal
total by 5.02%, and process wall by 5.64%. The candidate performed no Level 0
file reread and no Level 1 design upload; the controls reread the design,
spent about 3.16 seconds reconstructing its cache, and made five uploads
totaling 14.22 GB.

The candidate's peak host RSS fell from about 14.9 GB to 1.17 GB. Retaining
the design increased peak GPU allocation from 28,322 to 32,124 MiB. Existing
eligibility and capacity checks remain in force, and the storage-backed
fallback remains available.

All 63 IRLS iterations, weighted products, scores, and solves matched. All
three valid runs produced the same LOCO SHA-256. An initial control invocation
failed before Level 0 because its cache parent directory was absent; it was
corrected before the valid old-new-old sequence and is excluded above.

### Priority 4: Cox path continuation

A fresh eight-trait survival Level 0 cache was generated at `68030b7`, then
replayed with ordinary IRLS, `path-newton`, and `newton-cg`.

| Selector | Level 1 (s) | Process wall (s) | Ordinary weighted solves | Path solves | Path-converged models |
| --- | ---: | ---: | ---: | ---: | ---: |
| `irls` | 248.255 | 271.37 | 337 | 0 | 0 |
| `path-newton` | 140.668 | 163.86 | 69 | 111 | 160/160 |
| `newton-cg` | 139.494 | 162.23 | 69 | 111 | 160/160 |

Path continuation reduced Level 1 by 43.34% (1.765x) relative to the final
warm IRLS control. Every eligible later-lambda model converged, with no
fallback, unavailable cached Gram, step halving, non-finite rejection,
objective rejection, or score rejection. Exact penalized-score and objective
checks guarded every accepted correction.

As intended, the two accelerated selector values took the same Cox route.
They selected the same ridge for all eight traits, had identical counters, and
produced eight byte-identical pairs of LOCO files. The timing difference
between them is measurement noise rather than a Cox Newton-CG effect.

#### Numerical and downstream sensitivity

Comparing Cox path continuation with ordinary IRLS:

- TIME2 through TIME8 LOCO files were byte-identical;
- TIME1 differed; across 11,499,443 comparable finite prediction values, the
  maximum absolute difference was `0.0445` and RMSE was `0.00823586`; and
- printed cross-validation values showed small differences while the selected
  ridge remained unchanged.

A focused CPU Stage 2 audit tested the first 50,000 variants in exact PVAR
order for TIME1/EVENT1. The deterministic extract contained 50,000 unique
valid IDs and had SHA-256
`79eaccf956e0e1d4bb57a916ed174673863fd45178bd81d563465578cf5ab1c3`.
IDs, row order, missingness, and non-numeric fields matched exactly.

| Field | Maximum absolute difference | RMSE | Correlation |
| --- | ---: | ---: | ---: |
| BETA | `0.0002719` | `0.0000261474` | `0.9999972701` |
| SE | `0.0000048` | `0.000000552` | `0.9999999999876` |
| CHISQ | `0.111` | `0.006981` | `0.9999977746` |
| LOG10P | `0.0244` | `0.002017` | `0.9999971337` |

The scientific-boundary audit found:

- identical top-100 sets, with maximum rank displacement 5;
- 999/1,000 overlap in the top-1,000, with one swap at the boundary;
- 286 versus 287 variants at `p <= 1e-5`, caused by one boundary crossing
  from `1.01193e-5` to `9.76180e-6`;
- identical genome-wide-significant sets at `p <= 5e-8` (110 variants);
- no sign changes among strong signals; and
- `z` correlation `0.9999973971`, maximum absolute `z` difference `0.01284`,
  with the `abs(z) >= 3` membership differences confined to that boundary.

Both Stage 2 runs completed 50,000 tests with no ignored, corrected, or failed
variants. Their process walls were 48.23 and 44.48 seconds, but this focused
audit was designed as a numerical gate, not a performance comparison.

This result does not satisfy the stricter downstream equivalence contract
previously met by binary path-Newton: the top-1,000 and `p <= 1e-5` sets are
not exactly preserved. It does preserve the model, ridge grid, selected ridge,
high-significance set, and signal directions in this test. The continuation
also uses exact score and objective acceptance, so the difference should be
described as an alternative tolerance-level numerical solution, not as an
unguarded approximation.

The 1.765x Level 1 speedup is large enough to retain the implementation behind
the already non-byte-identical optimizer selector. It remains disabled by
default, and users choosing it for survival analyses should expect small
changes around ranking and significance cutoffs.

## Final assessment

Priorities 2 and 3 are safe default optimizations: they avoid redundant
transport or computation while preserving the ordinary algorithm and exact
serialized outputs. Priority 3 has the larger practical effect for its
eligible P=1 workload, at the cost of additional temporary GPU residency.

Priority 4 is an effective speed-first option, but not a free optimization.
Its numerical core is isolated in `Step1_Cox_Path_Newton`, while the changes
to the older Cox ridge path are limited to integration and state transfer.
The existing enum, bounded correction core, exact acceptance guards, and
ordinary-IRLS fallback are appropriate. The measured Cox sensitivity is more
visible than the earlier binary path-Newton sensitivity, so it should remain
explicitly experimental.
